# AI 서비스의 평가와 피드백

## 1. 검색 결과 Score만으로 충분하지 않은 이유
Vector DB가 반환하는 유사도 스코어(Score)는 단지 "질문 텍스트와 문서 텍스트가 임베딩 공간에서 얼마나 가까운가"를 나타냅니다. 
하지만 사용자가 진정으로 원했던 답변을 LLM이 제대로 생성해냈는지는 스코어만으로 알 수 없습니다.

## 2. 사용자 피드백(Feedback)의 중요성
따라서 실제 서비스 환경에서는 사용자가 답변을 읽고 남기는 명시적/암시적 피드백(👍/👎, 댓글 등)이 가장 확실한 평가 지표가 됩니다. 
이를 통해 우리는 어떤 종류의 질문에 시스템이 약한지 파악할 수 있습니다.

## 3. RAG 개선 루프
저장된 질문(Question)과 소스(Sources), 답변(Answer), 그리고 사용자 피드백(Feedback)을 묶어 데이터화하면 다음과 같은 RAG 개선 사이클이 가능해집니다:
1. 사용자가 질문하고 답변을 받음
2. 만족스럽지 않은 답변에 👎 피드백을 남김
3. 운영자는 로그를 분석하여 원인을 파악함 (검색이 잘못되었나? 프롬프트가 모호했나?)
4. 검색 알고리즘 고도화 또는 프롬프트 엔지니어링을 수행하여 시스템을 개선함
