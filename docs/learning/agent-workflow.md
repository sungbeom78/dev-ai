# Agent Workflow 도입 이유

## 1. 단순 RAG의 한계
기존의 `/ask` API는 모든 질문에 대해 "무조건 검색하고 무조건 답변을 생성하는" 구조입니다. 
하지만 사용자의 질문에는 "인사말", "시스템 사용법 묻기", "도메인 외의 엉뚱한 질문" 등이 포함될 수 있습니다. 단순 RAG는 이런 질문에도 억지로 문서 검색을 시도하여 엉뚱한 답변을 내놓거나 불필요한 LLM API 비용을 소모합니다.

## 2. 질문 분류(Intent Classification)의 필요성
Agent Workflow는 질문을 먼저 파악하여 **적절한 처리 경로로 분기(Routing)** 합니다.
- 시스템 사용법이라면 → 검색 없이 정해진 매뉴얼 출력
- 투자 추천이라면 → 단호하게 서비스 범위 밖임을 고지
- 진짜 지식 질문이라면 → 그때 비로소 RAG 파이프라인 수행

## 3. 실무적 가치
이러한 워크플로우 제어는 실제 AI 서비스에서 **사용자 경험(UX) 개선**, **운영 비용(LLM Token) 절감**, **보안/가드레일 준수**를 위해 필수적입니다. LangGraph는 이러한 파이프라인을 시각적으로도, 코드 레벨에서도 매우 명료하게 설계할 수 있게 도와줍니다.
