# 학습 및 포트폴리오용 설명 페이지 고도화 (Phase 8.2)

## 1. 기존 UI의 문제점 (테스트 콘솔 중심)
기존 RAG Web UI는 기능을 호출하고 API 결과를 검증하기 위한 "테스트 콘솔" 성격이 강했습니다.
단순히 버튼과 폼(form)만 나열되어 있다 보니, 외부 방문자나 채용 면접관이 이 페이지에 접속했을 때 "어떤 문제를 해결하려고 만든 시스템인가?", "각 버튼이 RAG 파이프라인에서 어떤 역할을 하는가?"를 파악하기 어려웠습니다.

## 2. 포트폴리오/학습 페이지로 개선한 이유
이 프로젝트의 주 목적은 "AI 백엔드 개발자로서의 역량 입증"과 "AI 기술(RAG, Vector DB, LangGraph)의 직접 구현을 통한 학습"입니다.
따라서, 방문자가 단순히 "코드가 돌아가는구나"를 넘어 "개발자가 이 아키텍처를 왜 이렇게 설계했는지"를 직관적으로 이해하도록 만들어야 했습니다.

## 3. 상단 설명 섹션의 역할
화면 상단에 기술 스택과 아키텍처 설명 섹션을 추가했습니다.
- **Hero & Why I Built This**: 단순 API 호출 이상의 데이터 파이프라인(Ingestion -> Indexing -> Retrieval -> Eval)이 필요함을 알림.
- **Architecture & Tech Stack**: Nginx, FastAPI, PostgreSQL, Qdrant 등 구성 요소가 왜 분리되었고 어떤 역할을 하는지 서술.
- **Data Storage Strategy**: PostgreSQL과 Qdrant가 왜 둘 다 필요한지(영속성과 벡터 검색의 차이)를 설명.
- **Agent & Reference Pipeline**: 기존 RAG를 넘어선 LangGraph 의도 분석과 자동 수집 아키텍처 비전 공유.

## 4. 기능 버튼보다 “흐름 설명”이 중요한 이유
단순히 "검색 버튼", "답변 버튼"만 있으면 RAG 원리를 이해하기 어렵습니다.
각 UI 섹션 위에 한국어로 1~3문장의 설명을 추가해, 이 단계가 RAG 전체 흐름에서 "문서를 쪼개는 단계인지", "벡터로 검색하는 단계인지", "LLM에 Prompt를 전달하는 단계인지" 명확히 인지하게 돕습니다.

## 5. 대상 독자 관점
- **면접관**: 사용한 기술과 아키텍처 설계 의도를 한눈에 파악 (`Portfolio Talking Points` 섹션 참고).
- **학습자 (나 자신)**: 향후 다시 코드를 열었을 때, RAG/Agent 파이프라인 구조를 빠르게 복기 가능.
- **일반 사용자**: 이 프로젝트가 단순히 만들어진 장난감이 아니라, AI 엔지니어링 랩이라는 것을 명확히 인지.
