# 임베딩(Embedding) 기초

## 1. Embedding이란 무엇인가?
텍스트, 이미지 등의 비정형 데이터를 컴퓨터가 이해하고 연산할 수 있는 **연속적인 실수형 벡터(배열)**로 변환하는 과정입니다.
RAG에서는 주로 "문서 Chunk"와 사용자의 "질문(Query)"을 각각 벡터로 변환합니다.

## 2. Embedding의 역할
임베딩의 가장 중요한 특성은 **의미(Semantic) 보존**입니다. 
- "사과"와 "바나나"는 벡터 공간 상에서 가깝게 위치하고, "자동차"와는 멀리 떨어지게 됩니다.
- 질문 "가장 큰 행성은?"과 문서 "목성은 태양계에서 가장 큽니다"는 단어는 다르지만 의미적으로 연결되어 두 벡터의 거리가 가깝게 맵핑됩니다.

## 3. RAG에서의 파이프라인
1. **문서 임베딩**: Chunk 단위로 나눈 문서를 OpenAI(`text-embedding-3-small`) 등의 모델을 통해 벡터로 변환하여 Vector DB에 저장합니다.
2. **질문 임베딩**: 사용자가 질문을 던지면, 해당 질문 텍스트 역시 **동일한 임베딩 모델**을 사용하여 벡터로 변환합니다.
3. 이 두 벡터의 거리(유사도)를 비교하는 것이 핵심 검색 과정이 됩니다.

## 4. 현재의 Mock Embedding 구현 (학습용)
현재 시스템에서는 OpenAI API Key가 없을 경우 데모를 진행할 수 있도록 `Mock` 모드를 지원합니다.
- 해시 함수 등을 사용하여 문자열에 대해 결정론적(Deterministic)인 벡터를 생성합니다.
- 이 방식은 같은 문자열이면 항상 같은 벡터를 내놓지만, "의미적 유사성"은 전혀 가지지 않습니다. 오직 "시스템 연동 테스트" 목적입니다.
