# 컨테이너 네트워크 및 포트 정책

## 1. 개요
단일 서버 환경 내에 백엔드 시스템, 데이터베이스, 벡터 저장소, 추후 배포될 프론트엔드 시스템 등 여러 컨테이너 서비스가 배포됩니다. 이에 따른 불필요한 Host 포트 노출을 방지하기 위한 포트 및 네트워크 정책을 수립합니다.

## 2. 데이터베이스 접근 정책
- **PostgreSQL**, **Qdrant**: 외부(Host)에서 직접 접근할 수 없도록 Host 포트 매핑을 제거하거나 로컬 전용으로 격리하는 것을 원칙으로 합니다.
- 모든 API 서버 및 데이터 처리 컨테이너는 Docker 내부 네트워크(`dev_ai_default` 등)를 통해 데이터베이스에 접근합니다.

## 3. 포트 노출 정책 (Phase별)
- **Phase 3 (현재)**: 빠른 개발과 CUrl/Postman 등의 API 검증 편의성을 위해 API 컨테이너를 `8000` 포트로 노출합니다.
- **Phase 5 (Web UI 도입 이후)**:
  - 외부로 노출되는 포트를 `8771` 하나로 줄이는 것을 목표로 합니다.
  - Web UI를 제공하는 컨테이너(Nginx 혹은 Node 기반 서버)가 `8771`을 점유하게 됩니다.
  - 외부에서 들어오는 `/api` 경로는 Web 컨테이너 내부의 Reverse Proxy를 거쳐 API 컨테이너의 내부 포트(`8000`)로 전달되도록 구성합니다.
  - 이를 통해 API 서버가 외부에 직접 노출되는 것을 막고, 보안 및 로드밸런싱 등 인프라 구성을 단일화할 수 있습니다.
