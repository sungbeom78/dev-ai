# Web UI 배포 및 포트 정책 (8771)

## 1. 개요
Phase 5에서는 클라이언트 브라우저에서 RAG의 전체 워크플로우를 모니터링할 수 있는 Web UI를 도입했습니다.

## 2. 8771 포트 선택 이유
- 시스템에는 이미 8000(API), 5432(DB), 6333(Qdrant) 등 주요 포트가 사용 중입니다.
- 개발 환경(특히 맥 OS나 윈도우 등)에서 자주 충돌하는 80, 8080, 3000, 5000 등을 피해 상대적으로 안전한 `8771` 포트를 이 프로젝트의 대표 Web 포트로 지정했습니다.

## 3. 네트워크 아키텍처 상태
- **Phase 5 (현재)**: 클라이언트(브라우저)는 Web UI(HTML/JS)를 `8771` 포트에서 제공받고, 데이터는 `8000` 포트의 API 서버에 직접 요청합니다. 이를 위해 API에 CORS(Cross-Origin Resource Sharing) 설정을 추가했습니다.
- **향후 계획**: Nginx의 리버스 프록시(Reverse Proxy) 기능을 고도화하여 클라이언트가 `/api/*` 경로로 요청하면 내부 Docker 네트워크를 타고 `api:8000`으로 전달되도록 수정할 계획입니다. 최종적으로는 8000 포트의 외부 노출을 막고 8771 단일 진입점만 유지하게 됩니다.
