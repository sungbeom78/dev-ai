# 의사결정: 기능 중심 UI에서 설명 중심 UI로 웹 페이지 개편 (Phase 8.2)

## 상황 (Context)
Phase 8.1까지 문서 등록, 청킹, 인덱싱, 의미 검색, Agent, 로그, 외부 수집(Reference) 등 AI 백엔드와 RAG 파이프라인에 필요한 대부분의 기능이 MVP 수준에서 완성되었습니다.
하지만, 브라우저에서 `localhost:8771`에 접속하면 버튼과 입력창만 나열되어 있어 처음 보는 사람이 이 프로젝트의 목적과 구조를 이해하기 어려웠습니다.

## 결정 (Decision)
**기존의 기능 테스트용 Web UI를 "포트폴리오 및 학습용 설명 페이지"로 전환하기로 결정했습니다.**
1. `index.html` 상단에 프로젝트 목표, 사용 기술, 시스템 구조, RAG 처리 흐름, 면접/포트폴리오 설명 포인트를 한국어로 자세히 서술했습니다.
2. 기존 기능 섹션(Document Ingestion 등)마다 해당 단계가 파이프라인에서 가지는 의미를 설명하는 한국어 텍스트를 추가했습니다.
3. 화면 최상단에 "Pipeline Step Navigator"를 두어, 단계별 흐름을 한눈에 보고 클릭하여 이동할 수 있게 만들었습니다.

## 이유 (Rationale)
1. README와 docs 폴더에 훌륭한 설명이 있더라도, 웹 페이지를 방문한 사용자는 문서를 먼저 읽지 않는 경우가 많습니다. 웹 브라우저가 첫인상을 결정합니다.
2. 기능의 갯수보다 "설계 의도와 파이프라인에 대한 이해도"가 훨씬 중요하기 때문입니다. PostgreSQL과 Qdrant를 왜 분리했는지, 왜 LangGraph를 썼는지 명확히 소통해야 합니다.
3. 이 도메인이 `ai.bomts.net`과 같이 외부에 공개될 것을 고려하여, 방문자에게 단순히 사용해 보라는 것이 아니라 "개발자의 역량과 기술 도입 이유"를 설명해야 합니다.

## 결과 (Consequences)
- 웹 페이지 스크롤이 상당히 길어졌으나, 상단 네비게이션(Pipeline Step Navigator)을 통해 원하는 기능으로 쉽게 이동할 수 있습니다.
- 프로젝트의 성격이 "데모 앱"에서 "AI Engineering Knowledge Lab"으로 명확해졌습니다.
- 코드와 API만 있던 프로젝트가 비로소 외부에 자신 있게 공유할 수 있는 포트폴리오 산출물로 시각화되었습니다.
