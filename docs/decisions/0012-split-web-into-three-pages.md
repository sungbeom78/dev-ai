# 0012. Split Web Into Three Pages

## Context
기존 `index.html`은 단일 페이지 내에 포트폴리오/설명 영역, 테스트 콘솔이 모두 섞여 있어, 전체 길이가 너무 길고 완성된 서비스처럼 보이지 않는 문제가 있었습니다.
단순 개발 랩실 수준을 넘어, 목적별로 체계화된 "서비스형 포트폴리오" 형태를 갖추기 위해 페이지 분리가 필요했습니다.

## Decision
웹 UI를 다음 3개의 페이지로 분리합니다.
1. `index.html`: AI 뉴스레터 (최신 AI 트렌드 및 기술 레퍼런스를 수집하고 한글로 RAG 검색하는 메인 서비스 화면)
2. `docs.html`: 프로젝트 문서 (왜 만들었는지, 아키텍처, 사용 기술, 설계 철학 등을 정리한 포트폴리오 설명용 페이지)
3. `test.html`: 테스트 콘솔 (기존에 있던 문서 등록, 청킹, 인덱싱, 검색, Agent, 로그 등 개별 기능을 실험하는 개발자용 페이지)

각 페이지는 공통된 상단 Navigation 바를 통해 이동하며, 동일한 테마와 스타일(`style.css`, `js/common.js`)을 공유합니다.

## Consequences
- 방문자(면접관 등)가 접속했을 때, 목적에 맞게 정제된 화면(뉴스레터/문서)을 먼저 보게 되므로 전문성이 강조됩니다.
- 개별 페이지의 코드가 간결해져 향후 유지보수와 기능 확장이 용이해집니다.
- 공통 Navigation 및 상태 표시 패널(`API: Online`)을 통해 전체 시스템이 안정적으로 운영되는 느낌을 줍니다.
