# 의사결정: AI 트렌드 소스 파이프라인 추가 (Phase 8)

## 상황 (Context)
Phase 1~7을 통해 문서를 등록하고, 청킹/임베딩하여 벡터 DB에 넣고, LangGraph 에이전트로 질문에 답하는 완벽한 RAG 파이프라인을 구축했습니다.
하지만 현재 시스템은 "사용자가 수동으로 텍스트를 복사해서 붙여넣어야만" 지식을 갖게 됩니다. 이는 실사용 관점에서 확장성이 매우 낮습니다.

## 결정 (Decision)
**자동화된 지식 수집 파이프라인(Source-based Ingestion)을 시스템에 통합하기로 결정했습니다.**
AI 분야의 유명 블로그, 튜토리얼 사이트, 릴리스 노트를 `Source Registry`로 관리하고, 이를 크롤링/추출하여 기존 RAG 파이프라인에 자동으로 적재합니다.

## 이유 (Rationale)
1. **지식의 최신성 유지**: AI 엔지니어링 도메인은 변화가 빠릅니다. 지속적인 파이프라인이 있어야만 에이전트가 "최신 트렌드"에 답할 수 있습니다.
2. **실제 서비스 아키텍처 모방**: 실제 기업 환경의 RAG 시스템은 단순히 DB만 띄워놓는 것이 아니라, 외부 데이터를 긁어와서(Ingestion) 정제하는 파이프라인이 아키텍처의 핵심입니다.
3. **포트폴리오 완성도**: 백엔드 개발자로서 데이터를 처리하고 스케줄링할 수 있는 파이프라인 구조를 보여주는 것은 매우 중요합니다.

## 결과 및 향후 계획 (Consequences)
- `trafilatura`와 `BeautifulSoup`을 활용해 외부 HTML 본문을 정규화된 텍스트로 추출합니다.
- `documents` 모델에 바로 연결하여, 기존의 Chunking 및 Indexing API를 수정 없이 재활용할 수 있게 설계했습니다.
- MVP에서는 CLI 기반의 수동 실행 스크립트로 동작하지만, 향후 Celery나 APScheduler 등을 통한 자동 스케줄링 배치 작업으로 쉽게 확장할 수 있습니다.
- 동일 페이지 중복 수집을 방지하기 위해 `CrawledPage` 모델을 통해 이력을 관리합니다.
